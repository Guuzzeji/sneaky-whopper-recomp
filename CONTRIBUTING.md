# Contributing

Thanks for helping. Read this page before you open a pull request.

## The one hard rule: no game data

Never commit or attach anything that comes from a game disc. That includes:

- ISOs, XBEs, XEXs, and the extracted `game/` folder
- `analysis/`, because it holds disassembly
- `src/recomp/gen/`, because it holds the lifted game code
- assets from the joke modes' reference games (`mw1/`, `skate3/`, `game/mods/`)
- screenshots or logs that dump large amounts of game code or data

`.gitignore` covers all of these. Don't weaken it. Pull requests that contain game data are closed.

## Where fixes go

`src/recomp/gen/` is regenerated by every lift, so never edit it by hand. Put a fix in one of these places:

| Problem | Where |
|---|---|
| One game function behaves wrongly | An override in `src/recomp_manual.c` |
| Graphics | `src/d3d9_hle.c` (Windows) or `src/gl_hle.c` (web) |
| Function boundaries, missed indirect-call targets | The seed lists in `seeds/` or the `tools.recomp` options (`CLAUDE.md`, "Debug loop") |
| A bug in the lifter or the Xbox runtime | `xboxrecomp/` |

If you change `seeds/`, `src/recomp_manual.c` overrides or the lifter, lift again (README, step 4) before you build.

## The toolkit

`xboxrecomp/` is a git subtree of [xboxrecomp](https://github.com/sp00nznet/xboxrecomp) with local patches. Keep toolkit changes in their own commits, apart from game changes, so they can go upstream:

```
git subtree split --prefix=xboxrecomp -b <branch>
```

Run the toolkit tests after you change it (from a VS developer prompt):

```
cd xboxrecomp
..\.venv\Scripts\python.exe -m pytest tools/ -q
```

If the tests fail with `PermissionError: [WinError 5]`, your machine blocks running new exes from `%TEMP%`. Point `TMP` and `TEMP` at a folder in the repo, for example `xboxrecomp\build\conftmp`.

## Before you open a pull request

1. Build the `release` preset and play the part of the game your change touches.
2. If you changed the web path, build `web` too, or at least `gl`.
3. Update the docs your change affects. Tick boxes in `docs/ROADMAP.md` when a roadmap item lands.
4. Describe what you tested in the pull request.

## Reverse-engineering the reference games

The joke modes follow how *Call of Duty 4* and *Skate 3* work. Study their binaries, write your findings in the docs, and write your own code. Never copy their code or ship their assets.

## Docs

`docs/BUILDING.md` explains how the pieces fit. `CLAUDE.md` holds the working notes: every command, every `RECOMP_*` switch and the debugging loop. It is written for AI coding assistants, but people can use it too.
